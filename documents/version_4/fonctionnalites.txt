# Fonctionnalités prévues version 4

- fonctionnalité 1 (personnalisé) : Nouveau Labyrinthe aleatoire
  - descriptif texte : Labryrinthe plus grand ajout de murs a l'interieur du labyrinthe pour rendre effectif le monstre fantome. Les murs au millieu sont généré aléatoirement.
  - critères de validation :
    - critère 1 les murs ne sont pas généré sur les personnages : monstres, héro
    - critère 2 les murs ne sont jamais exactement au même endroit
    - critère 3 il faut obligatoirement des murs sur les cotés 
  - responsables : Jules
	- Labyrinthe() : Jules
	- TestLabyrinthe : Jules



- fonctionnalité 2 : Fantômes , Ogre (personnalisé)
  - descriptif texte : Le labyrinthe dispose d'un nouveau type de monstre : les fantômes. Les ogres sont juste un type de monstres normaux.
  - critères de validation :
    - critère 1 Les fantômes peuvent traverser des murs mais pas les autres personnages (les autres monstres ou le héros)
    - critère 2 Les autres monstres continuent à être bloqués par des murs.
  - responsables : Ange
	- Personnage : Ange
	- Ogre : Ange
	- Fantome + deplacer() : Ange
	- Monstre + deplacer() : Ange
	- TestMecaniqueMonstre : Ange

# Bilan
Aujourd'hui, nous avons transformer totalement le gestionnaire de personnages , nous avons compris que par la suite nous allons devoir ajouter différents Personnage et différents Monstre. Ainsi nous avons transformer l'interface Personnage en une classe abstraite avec les attributs et getter. Creation de la classe abstraite Monstre et des classes ogre (juste un monstre normal) et Fantome (Monstre qui traverse les murs).
Pour que les fantommes soit fonctionnel nous avons agrandis le labyrinthe et mis en place une boucle pour génerer des murs au millieu du labyrinthe.
Problème : l'apparitions des murs du millieu peut bloqué des monstres mais très rarement le personnage. Car nous avons implémenter un systeme de deplacement en diagonal du Hero type jeu de dame(QZ / QS / SD / ZD).
